Sentry Issue

This PR stops the Fern task review panel from crashing when you switch between task artifacts that remount article editors with different document shapes. The fix makes the code block node view treat transient stale positions as non-fatal instead of resolving them against the new document and throwing.

**What Changed**

A small shared helper now safely checks whether a code block is inside a `multiCode` parent. `CodeBlockRenderer.svelte` uses that helper instead of calling `editor.state.doc.resolve(pos)` directly during render.

**Why It Happened**

Sentry showed the crash inside `getMultiCodeContext` while the user was clicking between Fern artifacts. Production data confirmed the source artifact had code blocks and the destination artifact was shorter, so an old code-block node view could briefly keep a stale `getPos()` value during teardown. Resolving that stale position against the new document raised the `RangeError`.
